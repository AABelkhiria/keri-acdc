# keri-acdc

ACDC credentials in Rust: the credential container and its self-addressing identifiers, the `iss`
and `rev` transaction events that record a credential's status, the seal and interaction event
that anchor them in the issuer's key event log, the CESR attachments that chain each artifact to
the next, and the five IPEX messages that disclose a credential. The behavior and wire bytes match
[signify-ts](https://github.com/WebOfTrust/signify-ts), checked against fixtures it generates.

Extracted from the signify-rs project.

## Modules

| Module | Purpose |
|---|---|
| `credential` | The credential container, its attribute block, the registry identifier, and the two SAIDs that give a credential its identity |
| `issuance` | The `iss` transaction event, the credential's attachment, and the artifacts of one issuance |
| `revocation` | The `rev` transaction event and the artifacts of one revocation |
| `transaction` | What both share: the transaction seal, the unsigned interaction event anchoring it, and the signed anchor |
| `ipex` | The `apply`, `offer`, `agree`, `grant` and `admit` exchange messages, the disclosure a grant carries, and the signed message |
| `error` | The transaction and IPEX errors |

Everything here is built unsigned and verified by bytes. Signing is the caller's, with whatever
holds its keys: `SignedAnchor` and `SignedIpexMessage` carry the result. Key management, the
client's identity and the KERIA agent model are not here; neither is submitting anything to an
agent.

Nothing in this crate reads a clock or a random source: timestamps and nonces are inputs, so every
artifact is reproducible.

## Use

```bash
cargo add keri-acdc
```

```rust
use keri_acdc::credential::{CredentialAttributes, CredentialBuilder, RegistryIdentifier};
use keri_acdc::issuance::IssuanceEvent;
use keri_acdc::transaction::{AnchorState, anchor_event};
use keri_protocol::prefix::IdentifierPrefix;
use keri_protocol::said::Said;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let issuer = IdentifierPrefix::from_qb64("EMQQpnSkgfUOgWdzQTWfrgiVHKIDAhvAZIPQ6z3EAfz1")?;
    let credential = CredentialBuilder::new(
        issuer.clone(),
        RegistryIdentifier::from_qb64("EGK216v1yguLfex4YRFnG7k1sXRjh3OKY7QqzdKsx7df")?,
        Said::from_qb64("EBfdlu8R27Fbx-ehrqwImnK-8Cm79sqbAQ4MmvEAYqao")?,
        CredentialAttributes::new("2023-08-23T15:16:07.553000+00:00".parse()?)
            .issuee(&IdentifierPrefix::from_qb64("EKvn1M6shPLnXTb47bugVJblKMuWC0TcLIePP8p98Bby")?)?
            .timestamp()?
            .text("LEI", "5493001KJTIIGC8Y1R17")?,
    )
    .build()?;

    // The issuance event the pinned signify-ts unit test publishes.
    let issuance = IssuanceEvent::for_credential(&credential)?;
    assert_eq!(issuance.said().qb64()?, "ENf3IEYwYtFmlq5ZzoI-zFzeR7E3ZNRN2YH_0KAFbdJW");

    // The issuer anchors it one event past its current key state, then signs that event.
    let state = AnchorState::new(issuer, 0, Said::from_qb64("EMwcsEMUEruPXVwPCW7zmqmN8m0I3CihxolBm-RDrsJo")?);
    let anchor = anchor_event(&state, &issuance.seal())?;
    assert_eq!(anchor.sequence_number(), 1);
    Ok(())
}
```

## Prerequisites

- Rust 1.97 or newer (`rustup` installs the toolchain pinned in `rust-toolchain.toml`).
- Nightly Rust and `cargo-fuzz`, only for fuzzing.
- Node 22 or newer and `git`, only to regenerate the fixtures.

## Build and test

```bash
cargo fmt --all -- --check
cargo clippy --all-targets
cargo test
cargo deny check
```

## Reference fixtures

`fixtures/` holds the expected outputs, in three groups generated by signify-ts at the commit
pinned in `tools/reference-vectors/package.json`. Tests read the fixtures and never need Node or
the network. Each fixture directory has a README with its provenance.

```bash
npm ci --prefix tools/reference-vectors
npm run --prefix tools/reference-vectors check      # regenerate and fail if anything changed
npm run --prefix tools/reference-vectors generate   # regenerate after an intended change
```

The generators read the reference's own TypeScript as well as running its compiled code, and the
npm package ships only the compiled half, so the first run checks the pinned commit out shallowly
into `tools/reference-vectors/.signify-ts/`, which is ignored by git.
